我将按照以下计划对项目进行重构和功能增强：

## 1. 数据层模块化 (Data Layer Refactoring)
**目标**：解耦 ViewModel 与 DAO，确保职责分明。
*   **创建 Repository**：新建 `com.yintianyan.tallybook.data.repository` 包。
*   **实现 TransactionRepository**：创建 `TransactionRepository` 接口及其实现类，封装 `TransactionDao` 的所有数据库操作。
*   **更新 ViewModel**：修改 `HomeViewModel`、`StatisticsViewModel` 等，将对 `TransactionDao` 的直接依赖改为依赖 `TransactionRepository`。

## 2. 屏幕文件结构重构 (Screen Structure Modularization)
**目标**：采用更紧密的集成方式（Feature-based），不再物理分离 View 和 ViewModel。
*   **重构 HomeScreen**：
    *   将 `screens/homescreen` 重命名为 `screens/home`。
    *   将 `view` 和 `viewmodel` 子包中的文件直接移至 `screens/home` 根目录，或按逻辑聚合。
    *   将通用的子组件（如筛选器相关）提取到 `components/common` 或保留在 `screens/home/components`。
*   **重构 StatisticsScreen & ProfileScreen**：
    *   整理文件结构，确保每个功能模块包含其所需的 UI 和逻辑文件。

## 3. UI 组件增强与拆分 (UI & Component Enhancement)
**目标**：提高复用性，实现可拖拽的记账按钮。
*   **实现 Draggable FAB**：
    *   创建 `components/DraggableFloatingActionButton.kt` 组件。
    *   实现拖拽手势监听 (`pointerInput`)。
    *   实现**吸附逻辑**：手指松开后，按钮自动吸附至屏幕右下方。
    *   **样式修改**：修改按钮形状为扩展型 FAB (ExtendedFAB)，包含图标和“记一笔”文本。
*   **组件拆分**：
    *   参考 `datepicker` 的模式，将 `TransactionList` 进一步拆分为 `TransactionGroupHeader` 和 `TransactionItem` 等原子组件。

## 4. 图标与主题优化 (Icon & Theme Polish)
**目标**：增强界面表现力，保持主题一致。
*   **图标更新**：在 `IconTheme.kt` 中引入更多 Material Icons，替换目前重复使用的占位图标，确保风格统一。
*   **主题保持**：严格使用 `MaterialTheme.colorScheme` 中的颜色定义，确保重构过程中视觉风格不变。

**执行顺序**：
1.  先进行数据层重构，建立 Repository。
2.  调整文件目录结构（这会涉及大量 import 修复）。
3.  实现 UI 组件拆分和 Draggable FAB。
4.  最后进行图标和细节优化。
